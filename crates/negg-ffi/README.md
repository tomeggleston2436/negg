# negg-ffi

A C ABI over `negg-session`, for hosts that are not Rust (Swift, C#,
Python's ctypes). The desktop app does not use it: the Tauri backend links
`negg-session` as Rust crates (ADR 0020).

## Owns

- The C ABI boundary: the `extern "C"` functions in `src/lib.rs` and the
  generated header `include/negg.h` (ABI version 1, `NEGG_ABI_VERSION`)
- The ownership and error rules of that boundary, below

## API

All functions are declared in `include/negg.h`.

- `negg_abi_version`
- `negg_open_roll(dir, &session)` opens a roll folder and runs its analysis
  to completion (pass 1 and the roll pool), so every later call sees a
  finished roll. It writes nothing. A failure to pool the roll is not a
  failure to open: the status is `NeggStatus_Ok`, the frames keep their own
  estimates and the pooling error is the thread's last error (so `Ok` with a
  non-empty last error means the roll opened but pooling failed)
- `negg_session_free` flushes the session once more, best effort (errors
  are dropped; a sidecar changed on disk is still never overwritten), then
  frees it; `negg_frame_count`
- `negg_render_tile(session, frame, level, tile_x, tile_y, buf, cap, &len)`
  renders one preview tile into a caller buffer, in the 48-byte-header RGBA8
  format of ADR 0022
- `negg_get_stats(session, frame, &json)` returns the frame's `FrameView` as
  JSON
- `negg_set_settings(session, frame, overrides_json)` and
  `negg_set_roll_settings(session, roll_json)` commit a whole
  `FrameOverrides` or `RollSettings` (JSON in the sidecar's snake_case) and
  flush the sidecars. The flush settles any pending re-pool, so a C host
  never sees one. The commit and the flush can fail apart: a refused commit
  (invalid JSON or settings, a read-only frame, a sidecar changed on disk)
  changes nothing, while a commit whose flush failed (a write error, another
  sidecar changed on disk) is kept in the session and the status is still
  `Session`; `negg_get_stats` shows the committed value, and the next
  successful flush (`negg_flush`, a setter, `negg_session_free`) writes it
- `negg_flush(session)` writes every pending edit now and reports a failure
  (`Session`, the message names the file); call it again to retry after
  fixing the cause
- `negg_export(session, frame, format, out_dir, &report_json)` exports one
  frame (`frame >= 0`) or the whole roll (`frame == -1`) as `negg convert` or
  `negg batch` would; `format` is 0 for TIFF16 and 1 for JPEG
- `negg_string_free`, `negg_last_error`

JSON carries settings, statistics and the export report only, never pixels.

## Ownership and errors

- Every fallible function returns a `NeggStatus` (an `int32_t`, `Ok` is 0):
  `Null` 1 (a required pointer was NULL), `Utf8` 2, `Json` 3 (a JSON argument
  did not parse, or a result could not be built), `NotFound` 4 (a frame index
  outside the roll), `BufferTooSmall` 5, `Session` 6 (the session refused or
  failed the call), `Panic` 7 and `Poisoned` 8.
- No panic crosses the boundary: each body runs under `catch_unwind`. A
  caught panic returns `Panic` and poisons the handle, and every later call
  on it returns `Poisoned`; free the handle and open the roll again.
- Strings that negg returns (`negg_get_stats`, the export report) belong to
  negg and are freed only with `negg_string_free`. NULL is a no-op there and in
  `negg_session_free`. Never pass any other pointer to either.
- Tile buffers belong to the caller. With a `cap` that is too small,
  `negg_render_tile` writes nothing, sets `*len` to the size needed and
  returns `BufferTooSmall`. `buf` may be NULL only with `cap == 0`, as a size
  query; the tile is still rendered, so a size query costs one full render.
- The last error is thread-local: the message of the last failure on the
  calling thread, copied by `negg_last_error(buf, cap)` into a caller buffer
  (truncated if needed, always NUL-terminated, returns the bytes needed
  including the NUL; `buf == NULL` with `cap == 0` asks the size). A
  successful call does not clear it; `negg_open_roll` sets it to the pooling
  error or to empty.
- A handle can be used from any thread: calls on one handle are serialised by
  an internal mutex. `negg_session_free` needs the only reference.
- Calls can block for a long time: `negg_open_roll` decodes and analyses the
  whole roll, and `negg_export` decodes and renders every frame it exports
  (minutes for a 36-frame roll of large RAW files). Any other call on the
  same handle waits for them meanwhile. Call these from a worker thread,
  never from a UI thread.

## Building and the header

`cargo build -p negg-ffi` builds `libnegg_ffi.a` (static) and the dynamic
library under `target/<profile>/`. `include/negg.h` is generated by cbindgen
and committed; the test `header_is_current` fails when it is stale. After
changing a signature or a doc comment on the ABI, regenerate it with

```sh
NEGG_BLESS=1 cargo test -p negg-ffi --test header
```

A change that is not backward compatible bumps `NEGG_ABI_VERSION`.

## Tests

- `tests/ffi.rs` drives the functions from Rust against a synthetic roll
- `tests/smoke.c` is the C smoke test: `tests/smoke.rs` compiles it with the
  system `cc` against the static library and `include/negg.h`, runs it on a
  synthetic roll and checks that it prints `smoke ok` and wrote an output
  (it is skipped, with a note, when there is no `cc` on `PATH`). To run it
  alone: `cargo test -p negg-ffi --test smoke`

## Must not

- Contain engine maths of its own
- Be depended on by any engine crate
