# negg-cms

Colour management: working space, ICC profiles and soft proof. Step 7 of
`docs/MATHS.md`.

## Owns

- `lab`: sRGB transfer functions (`srgb_eotf`, `srgb_oetf`), the D65
  sRGB-to-XYZ matrix, CIE 1976 L*a*b* (`xyz_to_lab`, `srgb_to_lab`) and
  the CIEDE2000 colour difference (`ciede2000`), verified against the
  34 published Sharma, Wu and Dalal test pairs
- `matrix`: pure 3x3 maths (`mul`, `mul_vec`, `inverse`, `transpose`),
  the Bradford chromatic adaptation (`bradford_adaptation`),
  `rgb_to_xyz_from_primaries`, the Rec.2020 primaries, D65 and D50, the
  lazily derived `REC2020_TO_XYZ` and `XYZ_TO_REC2020`, and
  `REC709_TO_REC2020`, the BT.2087 matrix by which a RAW's print channels
  enter the working space (ADR 0026: they are read as Rec.709 primaries with
  a D65 white), `camera_to_rec2020`, the white-normalised camera-to-Rec.2020
  matrix of ADR 0012 (`XYZ_TO_REC2020 * Bradford(W -> D65) * inverse(X2C) *
  diag(X2C * W)`, so a camera neutral stays neutral), which no step uses
  since ADR 0026 and which stays for the rig and print characterisation, and
  `icc_colorants_to_rec2020`, the entry for an ICC TIFF from its colorant
  tags (`XYZ_TO_REC2020 * Bradford(D50 -> D65) * C`). `f32` API, `f64`
  inside
- `profiles`: ICC version 4 profiles generated by Little-CMS from
  primaries and curves, never from binary files in the repository:
  `working_profile` (linear Rec.2020, D65, gamma 1.0) and
  `output_profile` / `profile_bytes` for sRGB, Adobe RGB compatible,
  Display P3, ProPhoto RGB and Rec.2020. Each carries a description tag
  (`negg <space>`) and a copyright tag
- `transform`: `working_to_output(space, intent)` builds an
  `OutputTransform` whose `apply` and `apply_u8` encode a linear Rec.2020
  `Image` as interleaved 16-bit or 8-bit RGB (the pipeline's single
  quantisation point), in parallel over bands with one Little-CMS
  transform per rayon worker; `icc_linearise_native` undoes the TRC of an
  embedded matrix/TRC profile per channel, leaving the image in the
  profile's own primaries, and returns the step 7 matrix out of them (LUT
  profiles are `Unsupported`); `gamma22_to_linear` is the fallback for
  16-bit TIFFs without a profile
- Soft proofing (later, with the display path)

## Threading

Little-CMS profiles and transforms are `Send` but not `Sync`, so none is
shared between threads. `OutputTransform::apply` and `apply_u8` already
run in parallel: they split the image into bands and each rayon worker
builds its own Little-CMS transform for the same space and intent; the
result is identical to one sequential transform (tested).
`icc_linearise_native` likewise gives each worker its own copy of the
curves. `Clone` for `OutputTransform` rebuilds its transforms (ADR 0013).

## Building

`lcms2` is pulled in with its `static` feature, so Little-CMS is compiled
from the vendored source in `lcms2-sys` with the `cc` crate. No system
library, `pkg-config` or package manager is needed on any platform; a C
compiler (MSVC on Windows) is the only requirement.

## Must not

- Decode or invert images
- Write output files
- Contain film or rig calibration maths
