# 0020: the app links the engine through negg-session; negg-ffi is a separate C ABI

## Status

Proposed, 2026-10-24 (Rulings 67, 68, 69 and 88).

## Context

Phase 3 adds a desktop app (Tauri 2 with a React frontend) and a C ABI for non-Rust hosts. Until now every flow (settings-file parsing, decode and prepare, rig and film loading, roll pass 1 and pooling, convert, batch, lock) lived in `negg-cli`, which also owns clap, printing, `eval` and `profile`. The app needs those flows without clap, and needs a long-lived session on top of them (cached analysis, history, tiles, scopes, thumbnails, export). The plan's one-pipeline rule applies: there must be no pixel maths outside `negg-render`, so whatever hosts the engine may move buffers but not compute values.

## Decision

1. **`negg-session` (Ruling 68).** A new crate, Apache-2.0 (it is orchestration moved out of the Apache-2.0 `negg-cli`, not engine maths), owns every flow: `convert_frame_with` (render, geometry, CMS, write, sidecar), `convert_one` (`negg convert`), `batch_dir` (`negg batch`), `lock`, roll pass 1 and pooling, settings-file parsing, and the `Session` type. `negg-cli` keeps clap, printing, `eval` and `profile`, and re-exports the moved items (`pub use negg_session::...`) so its tests compile unchanged. `negg-ffi` and the Tauri crate call only `negg-session`, plus `negg-types` for data types.
2. **The app does not use the C ABI (Ruling 67).** The Tauri backend links the engine as Rust crates through `negg-session`. `negg-ffi` is a thin C ABI over the same `negg-session` API for hosts that are not Rust (Swift, C#, ctypes), tested on its own.
3. **Separate cargo workspace for the app (Ruling 69).** `app/src-tauri` has its own `[workspace]`, its own `Cargo.lock`, and path dependencies on `crates/negg-session` and `crates/negg-types`. Its third-party crates are pinned in its own `Cargo.toml`. CI runs it in a separate `app` job on ubuntu with the Tauri 2 Linux packages.
4. **C ABI rules (Ruling 88).** Status codes; never a panic across the boundary (`catch_unwind`, and a caught panic poisons the handle); caller-allocated tile buffers; strings allocated by negg are freed only by `negg_string_free`; the last error is thread-local and copied into a caller buffer; a handle is usable from any thread (an internal `Mutex`); JSON only for settings and stats, never pixels. The header is generated by cbindgen and committed, and a test fails when it is stale (`NEGG_BLESS=1` rewrites it).

## Consequences

- **No C hop in the app.** Same process and language, so no unsafe code, manual marshalling or second error model between the UI and the engine. The cost of choosing wrongly is that the Tauri commands are rewired onto `negg-ffi` calls (about a day); no logic moves.
- **Single source of behaviour.** The CLI and the app run the same functions, which is what lets ADR 0024 test byte parity between them.
- **Independence from GUI libraries.** Tauri's `generate_context!` needs the built frontend, and Linux needs webkit2gtk development packages. Keeping the app out of the root workspace keeps `cargo test --workspace` and every engine task free of Node and system GUI libraries. Cost of choosing wrongly: one `members` line and a CI merge.
- **`negg-session` must not hold pixel maths.** Buffer layout moves (crop, quarter turn, flip) are not maths and live in `negg-types` (ADR 0021).
- **ABI cost.** A wrong ABI shape means ABI version 2. The header test makes accidental drift visible.
- **Licences.** `negg-session` and `negg-ffi` are Apache-2.0 like `negg-cli`; the engine crates keep their existing licences.

## Eval delta

None, no render change. Moved code is exercised by the unchanged `negg-cli` tests (stdout, stderr and bytes).
