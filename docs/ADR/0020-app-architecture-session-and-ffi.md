# 0020: the app links the engine through negg-session; negg-ffi is a separate C ABI

## Status

Accepted, 2026-10-24 (amended below).

## Context

Phase 3 adds a desktop app (Tauri 2 with a React frontend) and a C ABI for non-Rust hosts. Until now every flow (settings-file parsing, decode and prepare, rig and film loading, roll pass 1 and pooling, convert, batch, lock) lived in `negg-cli`, which also owns clap, printing, `eval` and `profile`. The app needs those flows without clap, and needs a long-lived session on top of them (cached analysis, history, tiles, scopes, thumbnails, export). The one-pipeline rule (ground rule 3 in `ROADMAP.md`) applies: there must be no pixel maths outside `negg-render`, so whatever hosts the engine may move buffers but not compute values.

## Decision

1. **`negg-session`.** A new crate, Apache-2.0 (it is orchestration moved out of the Apache-2.0 `negg-cli`, not engine maths), owns every flow: `convert_frame_with` (render, geometry, CMS, write, sidecar), `convert_one` (`negg convert`), `batch_dir` (`negg batch`), `lock`, roll pass 1 and pooling, settings-file parsing, and the `Session` type. `negg-cli` keeps clap, printing, `eval` and `profile`, and re-exports the moved items (`pub use negg_session::...`) so its tests compile unchanged. `negg-ffi` and the Tauri crate call only `negg-session`, plus `negg-types` for data types.

   What the move added to keep the CLI's text and exit codes identical: `OutputRequest` carries `crop`, `analysis_area` and `settings_file` next to the already parsed `settings`, and the flow reads the file at the same point the CLI always read it, so the winning error and exit code are unchanged (`settings` takes precedence); `FlowEvent` gains `Note`, `PoolRejected` and `NeedsAnalysisArea`; `lock_frame`, `Locked`, `read_settings_file` and `Format::extension` are public; the library wrappers `convert_frame` and `convert_frame_with` print a frame's notes after the conversion succeeds, so the binary's timing is unchanged. The `Session` is in `session.rs`, its views and the export request in `view.rs`, and the tile and scopes byte layouts in `wire.rs`. The tile side is `negg_render::TILE_SIZE` (512, ADR 0022); `negg-session` and the wire format use it and never define their own.
2. **The app does not use the C ABI.** The Tauri backend links the engine as Rust crates through `negg-session`. `negg-ffi` is a thin C ABI over the same `negg-session` API for hosts that are not Rust (Swift, C#, ctypes), tested on its own.
3. **Separate cargo workspace for the app.** `app/src-tauri` has its own `[workspace]`, its own `Cargo.lock`, and path dependencies on `crates/negg-session` and `crates/negg-types`. Its third-party crates are pinned in its own `Cargo.toml`. CI runs it in a separate `app` job on ubuntu with the Tauri 2 Linux packages. It is the package `negg-app` (library `negg_app_lib`), and its `rust-version` is 1.90 because Tauri 2.12 needs it; the root workspace stays at 1.89. It adds `negg-io` as a path dependency only to ask whether a roll has a `roll.negg.json` (ADR 0023); the session reads and writes every sidecar. The Tauri commands take snake_case arguments (`#[tauri::command(rename_all = "snake_case")]`). The root `deny.toml` is the only licence and advisory configuration for both workspaces; it carries one advisory ignore, RUSTSEC-2024-0370 (`proc-macro-error` is unmaintained, not vulnerable, and reaches the app only through gtk 0.18 on Linux), instead of a blanket `-W unmaintained`, and the app's `cargo deny` run passes it with `--config deny.toml` before `check`.
4. **C ABI rules.** Status codes; never a panic across the boundary (`catch_unwind`, and a caught panic poisons the handle); caller-allocated tile buffers; strings allocated by negg are freed only by `negg_string_free`; the last error is thread-local and copied into a caller buffer; a handle is usable from any thread (an internal `Mutex`); JSON only for settings and stats, never pixels. The header is generated by cbindgen and committed, and a test fails when it is stale (`NEGG_BLESS=1` rewrites it).

   `negg_open_roll` opens the roll and then runs `analyse_next` to Done, as `Session::analyse_all` does, so every later call sees a finished roll. A failure to pool the roll (for example a frame sidecar with invalid settings) is treated as non-fatal: the call returns Ok with the handle, the frames keep their own estimates, and the pooling error is recorded as the calling thread's last error, so Ok with a non-empty `negg_last_error` means the roll opened but pooling failed. The setters flush on every call, and a flush settles any pending re-pool (ADR 0023), so a C host never sees a pending pool. A setter whose commit succeeded but whose flush failed returns `Session` with the edit kept in the session; `negg_flush` writes pending edits on demand (and reports a failure), and `negg_session_free` flushes once more, best effort, before it frees the handle. `negg_open_roll` and `negg_export` can block for minutes on a large roll, and other calls on the handle wait for them (the crate's README).

## Consequences

- **No C hop in the app.** Same process and language, so no unsafe code, manual marshalling or second error model between the UI and the engine. The cost of choosing wrongly is that the Tauri commands are rewired onto `negg-ffi` calls (about a day); no logic moves.
- **Single source of behaviour.** The CLI and the app run the same functions, which is what lets ADR 0024 test byte parity between them.
- **Independence from GUI libraries.** Tauri's `generate_context!` needs the built frontend, and Linux needs webkit2gtk development packages. Keeping the app out of the root workspace keeps `cargo test --workspace` and every engine task free of Node and system GUI libraries. Cost of choosing wrongly: one `members` line and a CI merge.
- **`negg-session` must not hold pixel maths.** Buffer layout moves (crop, quarter turn, flip) are not maths and live in `negg-types` (ADR 0021).
- **ABI cost.** A wrong ABI shape means ABI version 2. The header test makes accidental drift visible.
- **Licences.** `negg-session` and `negg-ffi` are Apache-2.0 like `negg-cli`; the engine crates keep their existing licences.
- **The app's events and refusals.** Besides `negg://analysis`, `negg://thumbs` and `negg://export`, the backend sends `negg://error` (`{ message }`) for an error no command returned: a debounced flush that refused to overwrite a sidecar, a pool that could not be made, or a refused close. A close, quit or open of another roll whose flush fails is refused once with the command error kind `unsaved` (the edits could not be written; the user is told), and the next attempt goes ahead without them; any new edit re-arms the warning. A close or quit while an export runs is refused at once (kind `exporting`) rather than waiting for it. Before the flush of a close or quit the backend sends `negg://closing` and waits up to 1.5 s for the `close_ready` command: the webview leaves the field being typed in (so its value commits), sends every queued edit and then answers, so an edit made in the last moments is in the flush; a webview that does not answer does not hold up the close. On macOS the Edit menu's Undo and Redo are negg's own items (Cmd+Z and Shift+Cmd+Z) and send `negg://menu` (`{ action }`), so they undo negg's edit history on every screen; elsewhere the webview binds the same keys. The app's Export waits for pass 1 and for a running export. The error kinds a command returns are `convert`, `no_frame`, `read_only`, `busy`, `stale`, `invalid`, `no_roll`, `unsaved`, `exporting` and `internal`.

## Eval delta

None, no render change. Moved code is exercised by the unchanged `negg-cli` tests (stdout, stderr and bytes).
